# Quality Attribute Scenarios

## Сценарии атрибутов качества

| ID | Источник стимула | Стимул | Среда | Артефакт | Реакция | Мера реакции |
| --- | --- | --- | --- | --- | --- | --- |
| QAS-01 | Покупатель | Открывает каталог товаров в мобильном приложении | Обычная нагрузка, мобильная сеть 3G/LTE | Мобильное приложение, каталог товаров | Система загружает и отображает товары | Первый товар появляется менее чем за 2 секунды. 99% запросов к API выполняются не дольше 1 секунды |
| QAS-02 | Инфраструктура | Один из работающих экземпляров приложения выходит из строя | Система обслуживает покупателей | Приложение, система управления контейнерами | Система автоматически исключает отказавший экземпляр и перенаправляет запросы на работающие экземпляры | Доступность каталога и приёма платежей остаётся не ниже 99,9% за 30 дней |
| QAS-03 | Покупатели | Число запросов к каталогу резко увеличивается во время рекламной кампании | Пиковая нагрузка | API, каталог товаров, база данных | Система увеличивает количество реплик и распределяет между ними запросы | 99% запросов к каталогу выполняются не дольше 1 секунды при согласованной пиковой нагрузке |
| QAS-04 | Платёжный провайдер | M-Pesa или Flutterwave не отвечает на запрос об оплате в установленное время | Покупатель оформляет заказ | Модуль оплаты, адаптер платёжного провайдера | Система сохраняет платёж в промежуточном статусе и проверяет результат операции, не создавая повторное списание | Повторных списаний нет. Операция не помечается как неуспешная без подтверждения её результата |
| QAS-05 | Инфраструктура | Основная база данных становится недоступной | Система обрабатывает заказы и платежи | База данных заказов и платежей | Система восстанавливает доступ к данным и возобновляет обработку операций | Работа восстановлена не более чем за 30 минут (RTO). Подтверждённые финансовые операции не потеряны (RPO 0) |
| QAS-06 | Провайдер уведомлений | SMS- или WhatsApp-провайдер временно перестаёт принимать сообщения | Система обрабатывает заказы и отправляет уведомления | Модуль уведомлений | Система сохраняет сообщения в очереди и возобновляет их отправку после восстановления связи | Принятые уведомления не теряются. Время ожидания в очереди контролируется |
| QAS-07 | Покупатель | Повторно отправляет запрос на оплату после обрыва интернет-соединения | Нестабильная мобильная сеть 3G/LTE | Мобильное приложение, модуль оплаты | Система распознаёт повторный запрос и возвращает состояние существующей платёжной операции вместо создания новой | Повторных списаний денег нет |
| QAS-08 | Команда разработки | Выпускает новую версию приложения | Система работает и обслуживает покупателей | CI/CD, приложение, система управления контейнерами | Новая версия развёртывается без остановки пользовательских операций. При ошибке выполняется возврат к предыдущей версии | Во время обновления доступность остаётся в пределах SLO. Возможен автоматизированный откат |

## Проверка сценариев

Для каждого сценария необходимо провести испытание, которое подтвердит выполнение установленного требования.

| Сценарий | Способ проверки | Ожидаемый результат |
| --- | --- | --- |
| QAS-01 | Открыть каталог на мобильном устройстве с ограниченной скоростью соединения | Первый товар отображается менее чем за 2 секунды, время ответа API соответствует установленному P99 |
| QAS-02 | Принудительно остановить один работающий экземпляр приложения | Запросы продолжают обрабатываться оставшимися репликами |
| QAS-03 | Создать искусственную пиковую нагрузку на каталог | Приложение масштабируется, время ответа остаётся в установленных пределах |
| QAS-04 | Смоделировать отсутствие ответа от платёжного провайдера | Платёж сохраняет промежуточный статус, повторное списание не создаётся |
| QAS-05 | Смоделировать отказ базы данных и выполнить восстановление | Работа возобновляется в пределах RTO, подтверждённые финансовые операции сохранены |
| QAS-06 | Отключить тестовое соединение с провайдером уведомлений | Сообщения остаются в очереди и отправляются после восстановления соединения |
| QAS-07 | Повторно отправить запрос с тем же идентификатором платежа | Система не создаёт вторую платёжную операцию |
| QAS-08 | Выполнить обновление приложения с последующей имитацией ошибки | Пользовательские операции продолжают работать, предыдущая версия восстанавливается |

Ограничение: для QAS-03 необходимо согласовать пиковую нагрузку в запросах в секунду (RPS). В имеющихся артефактах есть прогноз количества пользователей, но отсутствуют подтверждённые значения RPS.
