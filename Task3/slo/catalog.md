# Контракт SLI, SLO и SLA каталога товаров

**Идентификатор:** SLO-CAT-01  
**Статус:** Проект, требует согласования CEO и CTO  
**Расчётный период:** последние 30 календарных дней

## Назначение

Каталог позволяет покупателю просматривать список товаров и карточки товаров. При его недоступности покупатель не может нормально выбрать товар и перейти к покупке.
- **SLI** — фактически измеряемый показатель качества сервиса.
- **SLO** — целевое значение, которого должна придерживаться техническая команда.
- **SLA** — гарантируемый бизнесу или клиенту уровень качества и порядок действий при нарушении.

## Контракт

| Показатель | Описание |
| --- | --- |
| Сервис | Каталог товаров |
| Основные операции | Открытие каталога, получение списка товаров, просмотр карточки товара |
| SLI доступности | Доля допустимых запросов к каталогу, завершившихся корректным ответом без технической ошибки |
| SLI производительности | P99 — время, за которое выполняются 99% запросов к API каталога |
| SLO доступности | Не менее 99,9% успешных запросов за последние 30 дней |
| SLO производительности | 99% запросов API выполняются не дольше 1 секунды |
| Пользовательское требование | Первый товар отображается на экране менее чем за 2 секунды |
| Предлагаемый SLA | Доступность не менее 99,5% за 30 дней |
| При нарушении SLA | Зарегистрировать инцидент, восстановить работу каталога, проинформировать ответственных со стороны бизнеса. Компенсации не определены |
| Проверка | Автоматические тестовые запросы (Synthetic Monitoring), метрики API, измерение загрузки каталога на мобильных устройствах в сетях 3G/LTE |

## Как рассчитывается доступность

**SLI доступности = количество успешных допустимых запросов / общее количество допустимых запросов × 100%.**

Ошибочные запросы самого пользователя, например запрос несуществующего товара, не считаются технической недоступностью, если система ответила корректно. Для P99 и доступности используются отдельные измерения.

При SLO 99,9% допустимая доля неуспешных запросов составляет 0,1%. Для ориентира это эквивалентно 43,2 минуты полной недоступности за 30 дней, но частичные ошибки могут исчерпать бюджет и без полной остановки каталога.

## Инциденты и действия

| Условие | Приоритет | Действие |
| --- | --- | --- |
| Каталог полностью недоступен более 5 минут | P1 — критический | Оповестить дежурного инженера и CTO, начать восстановление |
| Доля успешных запросов ниже целевого уровня в течение 15 минут или P99 превышает 1 секунду в течение 15 минут | P2 — высокий | Зарегистрировать инцидент, проверить API, базу данных, кеш и нагрузку |
| Израсходовано 50% бюджета ошибок за 30 дней | Предупреждение | Оценить причину и риск нарушения SLO |
| Израсходовано 100% бюджета ошибок | Нарушение SLO | Разобрать причины, ограничить рискованные обновления до стабилизации |

## Допущения
1. SLO 99,9%, P99 не более 1 секунды и SLA 99,5% являются проектными значениями, ещё не согласованными бизнесом.
2. Порог 5 минут для P1 и 15 минут для P2 предложен для MVP и требует согласования с эксплуатацией.
3. Требование о первом товаре менее чем за 2 секунды взято из Артефакта 2. Условия измерения на конкретных мобильных устройствах и сетях требуют уточнения.
4. Для окончательной проверки P99 нужен согласованный профиль нагрузки, включая пиковый RPS.
