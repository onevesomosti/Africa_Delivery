# Africa Delivery

Учебный проект по проектированию архитектуры мультикатегорийного маркетплейса для африканского рынка. Материалы охватывают путь от анализа противоречивых требований до выбора архитектуры, обеспечения качества и планирования развития.

Первый релиз (MVP) должен запустить пилот в Нигерии и Кении к **15 октября 2026 года**: каталог из **5000 товарных позиций от 100 продавцов**, оформление заказа, оплата через M-Pesa и Flutterwave, SMS и сообщения в мессенджерах, простой кабинет покупателя и базовая аналитика для CEO. Основные ограничения — нестабильный мобильный интернет, требования к обработке персональных данных, технические регулярные расходы до **$5000 в месяц** и команда из шести контракторов.

В проекте предложен модульный монолит с подключением платёжных и логистических партнёров через API и отдельными контурами данных по странам. Дальнейшее развитие ориентировано на пять стран, аудиторию более миллиона пользователей и продажи между компаниями (B2B) в течение года.

## Структура проекта

| Папка | Содержание |
| --- | --- |
| [Task1](Task1/README.md) | Контекст и требования. Разбор исходных материалов: цели маркетплейса, заинтересованные стороны, противоречия и вопросы, которые нужно решить до выбора архитектуры. |
| [Task2](Task2/README.md) | Выбор архитектуры. Предложение архитектуры первого релиза и её развития, сравнение альтернатив по срокам и стоимости, материалы для обсуждения на встрече в Найроби. |
| [Task3](Task3/README.md) | Качество и надёжность. Измеримые требования к работе платформы в нестабильных мобильных сетях: скорость, доступность, защита операций и обнаружение сбоев. |
| [Task4](Task4/README.md) | Размещение и восстановление. Предварительная схема размещения компонентов и данных по странам с учётом правовых ограничений, резервирования и восстановления после отказов. |
| [Task5](Task5/README.md) | Развитие платформы. План перехода от первого релиза к работе в новых странах: возможности бизнеса, этапы реализации, зависимости, команда и риски. |

В README каждой папки приведён полный список её проектных файлов с краткими описаниями. Материалы удобно читать последовательно: Task1 → Task2 → Task3 → Task4 → Task5.

## Форматы и статус материалов

Документы представлены в Markdown (`.md`), исходники схем — в PlantUML (`.puml`), готовые изображения — в PNG. В Task2 также находятся расчёт стоимости в Excel и слайд в PDF. ADR — документы с обоснованием архитектурных решений; SLO — целевые уровни качества работы сервисов.

Решения, расчёты и этапы развития отражают учебные проектные предложения и допущения. Их наличие не подтверждает согласование решений, заключение договоров, результаты испытаний или фактический запуск платформы.
